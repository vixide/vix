# Releasing Vix from a Mac

`scripts/release-local` is the local release path (T766): it builds the three
release targets, checksums them, signs the checksums with the maintainer's SSH
key, and can upload them to GitHub and Codeberg. **Cutting a tag stays the
maintainer's decision.** The script never creates or pushes a tag unless given
the separate `--tag` flag, and `.github/workflows/release.yml` (generated by
`dist`) stays as the manual fallback. It has not been run for real; the first
real use is the maintainer's.

## Steps

1. Cut the changelog: `CHANGELOG.md` needs a `## [2.0.0]` section (not just
   `[Unreleased]`) and the workspace version must match.
2. Run the whole gate on the commit to release and record it:
   `scripts/attest` (see [Contributing](../contributing-workflow.md)).
3. Rehearse: `scripts/release-local 2.0.0 --dry-run`. This checks the
   preconditions, runs `make build-macos build-windows build-linux`, writes
   `target/release-local/2.0.0/`, signs it, and prints the exact `gh` and `tea`
   commands an upload would run. It uploads nothing and tags nothing. The default
   (no flags) behaves the same.
4. Check the result as a downloader would:
   `scripts/release-local --verify-dir target/release-local/2.0.0`.
5. Decide about the tag. `scripts/release-local 2.0.0 --tag` makes a signed
   annotated tag locally and nothing else. Pushing it is yours to do, and pushing
   it also starts `release.yml`, which would build and create the same release,
   so decide which path is the release before you push.
6. Upload: `scripts/release-local 2.0.0 --publish`. It refuses unless the tag
   already exists on both forges, asks you to type
   `publish 2.0.0 to github codeberg` exactly, then runs `gh release create
   --verify-tag` (or `gh release upload --clobber` when the release exists) and
   `tea releases create`.

## What it refuses

A tree that is not clean, a branch other than `main`, a `HEAD` tree without a
valid full-tier attestation (`scripts/attest --verify`), a version that is not
the workspace version or has no changelog section, a missing build tool or cross
linker, and (for `--publish`) a missing tag or a confirmation that does not match.

## Assets

For each target the script writes `vix-tui-<target>.tar.xz` (`.zip` for Windows),
a matching `.sha256`, one `SHA256SUMS`, and `SHA256SUMS.sig`
(`ssh-keygen -Y sign -n vix-release`, verified with the allowed signers file that
signs commits). A downloader verifies with `scripts/release-local --verify-dir DIR`
or `ssh-keygen -Y verify -n vix-release`.

## Packaging handoff

`scripts/packaging render 2.0.0 --sums target/release-local/2.0.0/SHA256SUMS`
reads the checksums to fill the winget, Scoop and AUR templates; nothing is
published. Honest limit: the packaging templates name the `dist` targets
(`*-pc-windows-msvc`, `*-unknown-linux-gnu`), while the Makefile builds
`x86_64-pc-windows-gnu` and `x86_64-unknown-linux-musl`, so `render` will report
the missing assets until a release carries the `dist` builds. Use the local
release for the macOS and static Linux/Windows binaries and `release.yml` for
the installers.
