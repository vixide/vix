# Quality Metrics

Generated by `cargo run --example list_commands -- --write` (T833) from the
source tree; do not edit by hand. `scripts/check` fails when it is stale.

Every number here is read from the files as text, with comments and the
contents of string literals skipped: no build, no test run, no network. So
the page is the same on every machine for a given commit, and a change
that adds tests, translations or allowlist entries shows up in its diff.
The counts are a scan, not the compiler's view: a test generated by a
macro other than `proptest!` is not counted, and lines include blank
lines and comments.

## Not on this page

Metrics that need a build, a long run or a particular machine are kept
where they are measured:

- **Line coverage**: `cargo tarpaulin --config tarpaulin.toml` (LLVM
  engine; `cargo llvm-cov` works too), locally through `bin/test-coverage`
  and in CI's coverage job; see [`spec/ci`](../../spec/ci/index.md).
- **Mutation score**: `.github/workflows/mutants.yml` runs `cargo mutants`
  weekly and uploads `mutants.out/`; see [`spec/test`](../../spec/test/index.md#mutation-testing).
- **Flakiness**: `scripts/flaky-hunt` reruns a test under load; see
  [`spec/test`](../../spec/test/index.md#flaky-tests).
- **Speed and memory**: the Criterion benchmarks and the `VIX_PROFILE`
  frame profile; see [Performance](../performance/index.md).
