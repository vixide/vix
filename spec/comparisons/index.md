# Comparisons

Simpler than Fresh Editor (~/github/sinelaw/fresh) because:
- No plugins
- No JavaScript
- No TypeScript
- No remote editing

More integrated out of the box than stock Vim and Emacs because:
- LSP, DAP, Tree-sitter, a fuzzy palette, multiple cursors and a Git client
  with hunk staging need no plugins or packages
- Left-side drawer is a file explorer
- Right-side drawer is a message explorer
- Bottom dock for logs/output/data (Run Command, workspace search)
- Switchable themes (Dark, Light, and more — all JSON themes)
- Switchable UI language (internationalization)

Vim and Emacs are the primary comparisons in every user-facing comparison
(README, `docs/compare`, the site); Micro is no longer one.

Easier for novices than vim because:
- The default keymap (Apple) is not modal — keyboard shortcuts are typical of
  macOS and Windows, for example Ctrl-C for Copy.
- Power users who prefer modal editing can opt into the **Vim keymap**
  (**View → Keymap…**); see `crates/vix-keymap-model/spec/index.md`.

Easier for novices than emacs because:
- The default keymap (Apple) uses macOS/Windows shortcuts, for example Ctrl-C for
  Copy; the menu bar is on by default; command names are typical (Copy/Paste,
  not Kill/Yank).
- Power users who prefer chords can opt into the **Emacs keymap**.

## Comparison and migration pages

The user-facing pages (T827):

- `docs/compare/index.md`, the matrix, plus one landing page each for the
  editors Vix is most often weighed against:
  `docs/compare/vix-vs-visual-studio-code/`, `docs/compare/vix-vs-neovim/`
  and `docs/compare/vix-vs-helix/`. Each has a side-by-side table, when to
  pick which, and how to switch.
- One `docs/vix-for-<editor>-users/` guide per editor a user migrates from:
  Vim, Emacs, Spacemacs, Helix, VS Code, IntelliJ (JetBrains), Eclipse,
  Sublime Text, Zed, Fresh, ttt, Atom and Notepad++. Atom is discontinued
  (archived by GitHub in 2022), so its page is written for users moving off
  it.

Rules for every such page:

- **Facts about Vix** cite the test or source file that checks them, in a
  footnote naming the file (so `scripts/check-docs` fails when the file goes
  away) and the test function.
- **Facts about the other editor** describe its documented default behavior
  and link its official documentation. No version-specific claims; when
  unsure, leave the claim out.
- **Key tables come from the generated references.** A guide for an editor
  Vix has a keymap for copies its key rows verbatim from
  `docs/reference/keybindings-*.md` (generated by
  `cargo run --example list_commands -p vix-tui -- --write`), behind a
  `<!-- keys-from: <relative path> -->` comment.
  `tui/tests/keymaps_reference.rs`
  (`copied_key_tables_match_the_generated_keybindings_references`) fails when
  a copied row no longer matches its reference. A row whose action has no
  title in the reference (its id shows in the Action column) is left out.
- **An editor with no Vix keymap** (Atom, Notepad++) says so and points to the
  closest keymap: VS Code for Atom, Sublime for Notepad++ (whose Find,
  Replace, Find in Files and Go to Line keys it shares), with the default
  Apple keymap as the other choice.
- Every page is listed in `docs/SUMMARY.md` and linked from
  `docs/migrating/index.md`.
